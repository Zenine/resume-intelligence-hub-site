# 奧德賽計畫

奧德賽計畫把一個職涯問題拆成三條刻意不同的未來路徑。它不是用來預測未來，而是在投履歷、報課程或啟動副業專案之前，先讓取捨浮出水面。

當使用者問「下一步做什麼」、考慮重大職涯變化，或遇到一個很誘人但需要投入學習成本的 JD 時，就可以使用它。

## 三路徑地圖

一次設計三條路，不要只給一條：

1. **底盤路徑**：穩定複利路線。保住使用者最重要的人生約束，同時增厚職涯資本。
2. **進攻路徑**：選擇性躍遷路線。只有當更大職位、平台或職責範圍的收益值得承受額外負荷時，才推進。
3. **期權路徑**：高上限路線。先用低成本實驗探索，等證據足夠再提高風險暴露。

具體命名可以因人而異，但三條路的邏輯必須真的不同。不要寫成同一個計畫的三個版本。

## 先問不可犧牲項

設計路徑前，先問使用者最不願意犧牲什麼。常見錨點包括：

- 現金流穩定
- 家庭或照護時間
- 地點穩定
- 健康和精力
- 自主度
- 上限和野心

然後用這個錨點給路徑排序。一個看起來很光鮮、但違反不可犧牲項的機會，不應該成為主路徑。它可以保留為期權路徑，並寫清觸發條件。

## 推演三到五年

每條路都寫一段簡短推演：

- **第 1 年**：使用者下一步真實會做什麼，而不是空泛願望。
- **第 3 年**：什麼樣的進展算有可信牽引。
- **第 5 年**：這條路可能形成什麼身份、市場位置和生活方式。
- **風險**：什麼事情會悄悄破壞計畫。
- **訊號**：哪些證據會讓這條路更強或更弱。

推演要誠實。Hub 不應該把每條路都寫成勵志故事。

## 把缺口轉成學習投資

當 JD 暴露能力缺口時，不要把整份 JD 變成學習大綱。按職涯回報給缺口分級：

- **必須學**：缺了就無法可信進入目標職位的門檻技能。
- **需要了解**：使用者需要評審、管理或討論，但不必親自成為專家的主題。
- **暫不主攻**：會把使用者從更強職涯資本上拉偏的相鄰主題。

這樣可以避免被單個 JD 帶偏。目標是投資那些能在多種未來裡複利的技能。

## 設計做中學專案

用有邊界的專案替代泛泛學習清單。好的專案應該包含：

- 一個真實工作流程
- 一個小而完整的資料集或場景
- 可見產物：README、demo、評估記錄、失敗案例
- 清晰技能映射：它證明什麼，不證明什麼
- 履歷邊界：現在能寫什麼，必須等真實落地後才能寫什麼

優先設計四到八週專案。時間夠產出證據，又不至於變成第二份工作。

## 保持履歷邊界誠實

Hub 要區分學習、實驗和已證明經驗：

- **已有佐證**：可以用於履歷和面試。
- **專案進行中**：可以放進 `todo.md` 或作品集，但不能過度包裝。
- **尚不可寫**：沒有證據前，不進入正式履歷。

這對資深職位尤其重要。把新技術棧硬寫成專家級，比承認自己有清晰學習計畫更傷可信度。

## 建議的 hub 輸出

完成奧德賽計畫後，在私有職涯 hub 裡保存這些產物：

- `career/odyssey/YYYY-MM-DD-plan.md`：三路徑推演。
- `jobs/market-watch/YYYY-MM-DD-<role>-gap.md`：針對某個 JD 的 gap 分析。
- `todo.md`：選定的實驗和證據收集任務。
- `changelog.md`：計畫、實驗或作品集產物完成後的歸檔記錄。

不要把私人家庭、薪酬、醫療或雇主敏感細節寫進公開文件。如果生成的 hub 需要保存這些資訊，要把檔案標為敏感。
