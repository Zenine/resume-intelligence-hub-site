# サンプル

このページは、`resume-intelligence-hub` がプライベートなキャリアハブを初期化した後に何を生成できるかを示す。以下はすべて合成・匿名化されたサンプルであり、架空の名前、架空の組織、架空の指標、相対パスのみを使用している。

## 安全上の注意

これらのサンプルは形式の参考であり、そのままコピーする主張ではない。実際のハブでは、機密原本を公開リポジトリの外に置き、検証済みの事実と下書きを分離し、高ステークス応募前に応募前検証を実行する。

## profiles/master.md の実績スニペット

```markdown
### プラットフォーム信頼性とインシデントノイズ削減

- 架空の分析プロダクトで 5 人のプラットフォームチームを率い、アラートルーティングのワークフローを再設計し、2 四半期で重複アラートを 43% から 12% に削減。
- 個人のオーナーシップ、チーム成果、顧客影響、未解決リスクを分けて記録する週次インシデントレビュー用テンプレートを構築。
- エビデンス状態：内部記録あり。外部利用前には公開情報源によるクロスチェックが必要。
- 帰属境界：ワークフロー設計とファシリテーションを担当。信頼性改善はプラットフォームチーム全体で達成。
```

## STAR ストーリー

```markdown
### ストーリー：ノイズの多いエスカレーション経路を減らす

**Situation**：架空のカスタマーオペレーションチームが、重複する監視ルールから繰り返しインシデント通知を受けていた。

**Task**：高重大度アラートを隠さずに、エスカレーション経路を明確化する。

**Action**：サポートリードにヒアリングし、アラートのオーナーシップを整理し、重複ルーティングルールを削除し、共通のインシデント分類に基づく週次レビューを導入。

**Result**：この合成サンプルでは、重複アラートが 43% から 12% に低下し、オンコールレビュー時間が 30% 減少し、チームは今後のサービス立ち上げにも分類体系を採用。

**面接での深掘り角度**：ツールだけでなく、曖昧な状況での判断を強調する。
```

## Verification log

```markdown
# 応募前検証ログ

応募：2026-04-15-exampleworks-platform-lead
レビュアー：AI エージェント + 人によるレビュー
状態：提出前に人の確認が必要

| 主張 | ソース種別 | 検証 | 結果 | 次のアクション |
|------|------------|------|------|----------------|
| 重複アラートを 43% から 12% に削減 | 内部ダッシュボード要約 | 対象期間と分母を比較 | 下書きのみ | エクスポート可能か確認 |
| 5 人チームを率いた | チームロスターのメモ | 役割と日付を確認 | 妥当 | 元マネージャーに表現を確認 |
| 週次インシデントレビュー用テンプレートを作成 | 内部プロセス文書 | 帰属境界を確認 | 下書き検証済み | 「作成」は維持し、経営判断を主張しない |
| 顧客影響の表現 | サポートチケットのテーマ | 根拠のない売上・解約主張を避ける | エビデンス不足 | ビジネス影響の主張を削除 |
```

## 四半期 SMART プラン

```markdown
# SMART プラン：2026 Q3

ポジショニングターゲット：中規模 B2B ソフトウェアチームの Platform Lead。

1. 2026-08-15 までに、エンジニアリングマネージャー 1 名とサポートリード 1 名のレビューを受けた信頼性関連の内部記事を 2 本公開する。
2. インシデント判断、トレードオフ説明、関係者調整に焦点を当てた模擬面接を毎月 1 回実施する。
3. 2026-09-10 までに、最も強い信頼性実績 3 件を STAR ストーリーに変換し、検証済みの帰属境界を補う。
4. 2026-09-30 までに、Platform Lead または Staff Platform Engineer の JD を 12 件収集し、スコープ、チーム規模、必要エビデンスでタグ付けする。
5. システム設計レビュー用パケットを完成させて資格ギャップを 1 つ閉じ、学びを `planning/quarterly-review-2026-q3.md` に記録する。
```

## これらのサンプルの使い方

重要なのは具体的な表現ではなく、ソースとなる事実、生成された下書き、面接ストーリー、検証エビデンス、四半期計画を分離すること。この分離により、AI エージェントは毎回の応募を一度きりの書き直しにせず、時間をかけて出力を改善できる。
