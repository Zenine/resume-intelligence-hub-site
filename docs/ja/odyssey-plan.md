# オデッセイプランニング

オデッセイプランニングは、1 つのキャリア上の問いを、意図的に異なる 3 つの未来に分けて考える方法です。未来を予測するためではありません。求人、学習コース、副業プロジェクトに引っ張られる前に、トレードオフを見えるようにするためです。

ユーザーが「次に何をすべきか」と聞いたとき、大きな転職を考えているとき、または本格的な学習投資が必要な魅力的な JD に出会ったときに使います。

## 3 つの道筋

1 つではなく 3 つの道を作ります。

1. **基盤ルート**：安定して複利を積むルート。ユーザーにとって最も重要な制約を守りながらキャリア資本を厚くします。
2. **ストレッチルート**：選択的に上を狙うルート。より大きな役割、プラットフォーム、スコープの価値が負荷に見合う場合だけ進めます。
3. **オプションルート**：高い上限を持つルート。証拠がそろうまでは低コストの実験として扱います。

名前はユーザーに合わせて変えてかまいませんが、3 つのロジックは明確に分けます。同じ計画の言い換えを 3 つ作らないでください。

## まず譲れないものを決める

道筋を設計する前に、ユーザーが最も犠牲にしたくないものを確認します。よくある軸は次の通りです。

- キャッシュフローの安定
- 家族やケアの時間
- 場所の安定
- 健康とエネルギー
- 自律性
- 上限と野心

その軸で道筋を並べ替えます。魅力的に見えても譲れない条件を壊す選択肢は、主ルートではありません。トリガー条件付きのオプションルートとして残します。

## 3 年から 5 年を見通す

各ルートについて短く予測します。

- **1 年目**：ユーザーが次に実際に行うこと。抽象的な願望ではありません。
- **3 年目**：信頼できる進捗がどのように見えるか。
- **5 年目**：その道が生む可能性のあるアイデンティティ、市場での位置、生活スタイル。
- **リスク**：計画を静かに壊すもの。
- **シグナル**：その道を強める、または弱める証拠。

予測は正直に書きます。すべてのルートを励ましの物語にしないでください。

## ギャップを学習投資に変える

JD がスキルギャップを見せたとき、JD 全体を学習シラバスにしないでください。キャリア上のリターンで分類します。

- **必ず学ぶ**：その役割に入る信頼性を左右する門番スキル。
- **理解しておく**：評価、管理、議論は必要だが、本人が専門家になる必要はないテーマ。
- **今はやらない**：より強いキャリア資本からユーザーを逸らす隣接テーマ。

これにより、1 つの JD に進路を振り回されにくくなります。複数の未来で複利になるスキルに投資することが目的です。

## 実践プロジェクトを設計する

一般的な学習リストではなく、範囲を切ったプロジェクトにします。良いプロジェクトには次があります。

- 1 つの実際のワークフロー
- 小さいが完結したデータセットまたはシナリオ
- 見える成果物：README、demo、評価メモ、失敗事例
- 明確なスキルマップ：何を証明し、何を証明しないか
- 履歴書上の境界：今言えること、実運用後まで待つべきこと

期間は 4〜8 週間を推奨します。証拠を出すには十分で、第二の仕事になるほど長くはありません。

## 履歴書上の境界を守る

Hub は学習、実験、証明済み経験を分けます。

- **証拠あり**：履歴書や面接で使えます。
- **進行中のプロジェクト**：`todo.md` やポートフォリオで追跡できますが、過大に主張しません。
- **まだ主張できない**：証拠ができるまで正式な履歴書には入れません。

シニア職では特に重要です。新しいスタックを専門家レベルだと誇張するより、焦点の合った学習計画を示す方が信頼されます。

## 推奨される hub 出力

オデッセイプランが完了したら、プライベートなキャリア hub に次を保存します。

- `career/odyssey/YYYY-MM-DD-plan.md`：3 ルートの予測。
- `jobs/market-watch/YYYY-MM-DD-<role>-gap.md`：特定 JD のギャップ分析。
- `todo.md`：選んだ実験と証拠収集タスク。
- `changelog.md`：計画、実験、ポートフォリオ成果物が完了したときの記録。

家族、報酬、医療、雇用主に関わる機密情報を公開ドキュメントに書かないでください。生成された hub に保存する場合は、そのファイルを機密として扱います。
