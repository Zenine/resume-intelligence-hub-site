# 奥德赛计划

奥德赛计划把一个职业问题拆成三条刻意不同的未来路径。它不是用来预测未来，而是让取舍在投简历、报课程或开副业项目之前先浮出水面。

当用户问“下一步做什么”、考虑重大职业变化，或遇到一个很诱人但需要投入学习成本的 JD 时，就可以用它。

## 三路径地图

一次设计三条路，不要只给一条：

1. **底盘路径**：稳定复利路线。保住用户最重要的人生约束，同时增厚职业资本。
2. **进攻路径**：选择性跃迁路线。只有当更大职位、平台或职责范围的收益值得承受额外负荷时，才推进。
3. **期权路径**：高上限路线。先用低成本实验探索，等证据足够再提高风险暴露。

具体命名可以因人而异，但三条路的逻辑必须真的不同。不要写成同一个计划的三个版本。

## 先问不可牺牲项

设计路径前，先问用户最不愿意牺牲什么。常见锚点包括：

- 现金流稳定
- 家庭或照护时间
- 地点稳定
- 健康和精力
- 自主度
- 上限和野心

然后用这个锚点给路径排序。一个看起来很光鲜、但违反不可牺牲项的机会，不应该成为主路径。它可以保留为期权路径，并写清触发条件。

## 推演三到五年

每条路都写一段简短推演：

- **第 1 年**：用户下一步真实会做什么，而不是空泛愿望。
- **第 3 年**：什么样的进展算有可信牵引。
- **第 5 年**：这条路可能形成什么身份、市场位置和生活方式。
- **风险**：什么事情会悄悄破坏计划。
- **信号**：哪些证据会让这条路更强或更弱。

推演要诚实。Hub 不应该把每条路都写成励志故事。

## 把缺口转成学习投资

当 JD 暴露能力缺口时，不要把整份 JD 变成学习大纲。按职业回报给缺口分级：

- **必须学**：缺了就无法可信进入目标岗位的门槛技能。
- **需要了解**：用户需要评审、管理或讨论，但不必亲自成为专家的主题。
- **暂不主攻**：会把用户从更强职业资本上拉偏的相邻主题。

这样可以避免被单个 JD 带偏。目标是投资那些能在多种未来里复利的技能。

## 设计做中学项目

用有边界的项目替代泛泛学习清单。好的项目应该包含：

- 一个真实工作流
- 一个小而完整的数据集或场景
- 可见产物：README、demo、评估记录、失败案例
- 清晰技能映射：它证明什么，不证明什么
- 简历边界：现在能写什么，必须等真实落地后才能写什么

优先设计四到八周项目。时间够产出证据，又不至于变成第二份工作。

## 保持简历边界诚实

Hub 要区分学习、实验和已证明经验：

- **已有佐证**：可以用于简历和面试。
- **项目进行中**：可以放进 `todo.md` 或作品集，但不能过度包装。
- **尚不可写**：没有证据前，不进入正式简历。

这对资深岗位尤其重要。把新技术栈硬写成专家级，比承认自己有清晰学习计划更伤可信度。

## 建议的 hub 输出

完成奥德赛计划后，在私有职业 hub 里保存这些产物：

- `career/odyssey/YYYY-MM-DD-plan.md`：三路径推演。
- `jobs/market-watch/YYYY-MM-DD-<role>-gap.md`：针对某个 JD 的 gap 分析。
- `todo.md`：选定的实验和证据收集任务。
- `changelog.md`：计划、实验或作品集产物完成后的归档记录。

不要把私人家庭、薪酬、医疗或雇主敏感细节写进公开文档。如果生成的 hub 需要保存这些信息，要把文件标为敏感。
